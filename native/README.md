# Нативный движок v8-chroma

Сборкой C++ управляет CMake; основной генератор — Ninja. Код подключения
и перехватов поддерживает Windows x64. Остальные платформы
проверяют переносимое Rust-ядро отдельно.

## Сборка

Для основной сборки нужны CMake 3.25+, Ninja, MSVC и Windows SDK.
Из x64 Developer Command Prompt или Developer PowerShell, в корне проекта:

```text
python -m pip install -r scripts/requirements-ci.txt
python scripts/build.py native
```

Или непосредственно из этого каталога:

```text
cmake --preset windows-msvc
cmake --build --preset windows-msvc
cmake --install ../build/native/windows-msvc --prefix .. --config Release
```

CMake описывает движок, mock DLL и тестовые процессы отдельными целями.
Ninja пересобирает изменённые файлы и их зависимости. `V8_CHROMA_BUILD_FIXTURES`
управляет сборкой тестовых программ. MSVC использует статический CRT.
Установка размещает движок в `../assets/ThemeProbe.dll` для встраивания в Rust,
а свои fixtures — в игнорируемых `bin/` и `../tests/fixtures/`.

Для разработки также есть preset `windows-mingw` (g++ в PATH) и `windows-zig`.
Последний читает абсолютный путь компилятора из переменной окружения `ZIG`.
Все три варианта используют один CMakeLists.txt. CI использует MSVC.
Личные пути можно задавать в игнорируемом CMakeUserPresets.json.

## Проверки

Из корня проекта `python scripts/build.py check` собирает native, затем запускает
проверки протокола, UI, Rust и сценарии на собственных процессах/fixtures.

Для проверок на Cairo установленной 1С добавьте `--cairo <platform-bin>/cairo.dll`.
Проверяются растровые элементы, выделение и production IAT на 13 темах и
диагностическом профиле. Платформенная DLL не распространяется проектом.

`browser_lifetime_test` проверяет запросы MSAA к уничтожаемому HTML-окну:
обычные запросы проходят, запросы `OBJID_CLIENT` внутри `DestroyWindow`
отклоняются, после неудачного уничтожения обработчик снимается. Проверка
production IAT повторяет этот сценарий через импорт `DestroyWindow` в собственном
WebKit-fixture до подключения, на всех темах и после остановки движка.

Протокол v3 имеет размер 4760 байт; его изменения требуют согласования
C++, Rust и независимых goldens. Уже загруженный движок не заменяется повторной
инъекцией; его обновление может требовать штатного перезапуска конфигуратора.

## Подсветка модулей

`ThemeProbe` включает TextMate, QuickJS и Oniguruma. CMake скачивает закреплённые
архивы нативных зависимостей при первой сборке и проверяет SHA-256.
Библиотека `vscode-textmate` и две грамматики `1c-syntax` встроены из `assets/syntax`.
Грамматика BSL включает грамматику запросов `source.sdbl` в подходящих строках.
Адаптер читает буфер после правки, Undo или Redo. Рабочий поток внутри
Конфигуратора сохраняет состояние грамматики между строками и возвращает
диапазоны UTF-16. Адаптер сверяет редакцию буфера и применяет диапазоны на
потоке окна. Цвета тем передаются записями `SyntaxColor` протокола v3.
Для выделенных токенов используется цвет текста выделения. Cairo-перехват
проверяет фон под глифом в пределах прохода отрисовки редактора BSL.
При `semantic_highlighting=false` менеджер исключает записи `SyntaxColor`.
Адаптер восстанавливает исходные диапазоны, а при повторном включении
заново обрабатывает открытые модули. Протокол сохраняет версию и размер.

Модули основной конфигурации и расширений используют общий путь через кэш
стилей редактора. Редактор результата сравнения и объединения использует тот
же кэш с лексером из `frntend.dll`. Две исходные панели сравнения работают с
текстовыми буферами без лексера. Адаптер распознаёт их при открытии или
обновлении сравнения модулей. Он меняет только цвет текста через нативный
интерфейс разметки строки, сохраняя заливку и выравнивание различий.
Переключение режима обновляет уже распознанные панели. Если сравнение
открыли до первого подключения ThemeProbe, откройте построчное сравнение
заново или выберите процедуру в структурном сравнении.

Неактивные MDI-заголовки, созданные после подключения темы, используют
штатный серый текст. Если он сливается с заливкой рамки, Cairo-перехват
проверяет фон под глифами и подбирает контрастный цвет заголовка.

Адаптер находит функции по сигнатурам машинного кода, проверяет связи вызовов
и таблицы виртуальных методов. По совпавшим признакам выбирает структуру
редактора 8.3 или 8.5. При несовпадении продолжает работать обычная цветовая
схема. При отключении темы адаптер возвращает исходные стили редактора.

Живой редактор проверен на Windows x64 с 8.3.26.1656, 8.3.27.2325, 8.5.1.1529
и 8.5.4.1878. `python scripts/build.py check` проверяет категории BSL и запросов,
переносы CRLF и позиции UTF-16. После сборки
`tests/fixtures/editor_syntax_discovery_test.exe "<каталог платформы>/bin"`
проверяет поиск интерфейса и отказ при изменении инструкции или адресата вызова.

Собственные значки встроены в ThemeProbe. Для генерации нужны Python и Pillow
из `scripts/requirements-ci.txt`; установленная 1С не нужна. CMake пересобирает
пакет при изменении SVG/профилей. `icon_theme_test` проверяет модуль на
собственных поверхностях без Cairo. `icon_bootstrap_test` проверяет production
bootstrap при отказе подготовки значков: цветовая тема остаётся активной,
а импорты значков возвращаются к штатным. Оба теста входят в `build.py check`;
см. [интеграцию](../docs/custom-icons.md).

## Шрифты

Отдельная `FontProbe.dll` из `src/font_probe.cpp` собирается и устанавливается
в `assets` для встраивания в EXE. Она загружается только при выборе шрифта;
по умолчанию используются параметры 1С. При включённых fixtures собираются
`font_shaping` и `font_discovery_test`. Первый проверяет Uniscribe и позиции
каретки без 1С и входит в `build.py check`. Второй принимает каталог установленной
платформы, проверяет обнаружение редактора без выполнения DLL и отказ при изменённой
структуре кода. [Устройство и проверки](../docs/fonts.md).

`UiFontEngine.dll` из `src/ui_font.cpp` управляет шрифтом интерфейса независимо
от редактора. Он обновляет стандартные шрифты через штатное событие стиля на
GUI-потоке. По умолчанию выбран Segoe UI Variable Small, отключение подмены
возвращает параметры 1С. `ui_font_policy_test` проверяет алиасы и сохранение
начертаний без 1С; `ui_font_discovery_test <platform-bin>` проверяет обнаружение
обычного и хвостового вызовов события на установленном core без его запуска.
Обе цели доступны при включённых fixtures.
