# Технический дизайн: Linux-шрифты и сохранение редактора

| Поле | Значение |

| Спецификация | [SPEC-LINUX-TEXT](linux-text-rendering.md) |

| Статус | Ревью |
| Декомпозиция | Линейная реализация: discovery → refresh → regression → реальный редактор |

## Обзор

HarfBuzz уже выполняет программные лигатуры, Cairo — сглаживание. Реальный дефект
находится в широком уведомлении параметров текста, сбрасывающем состояние BSL.

## Стратегия решения

Сохранить shaping и растеризацию; обновлять только штатный Font контроллеров.
Не вызывать общий callback настроек текста и не уведомлять адаптер документа.

## Структурные блоки

- `elf.h`: проверенные диапазоны ELF и границы функций из GNU unwind index.
- `editor_refresh.h`: обнаружение обработчика по GUID, загрузчика Font,
  преобразования масштаба, присваивания и setter; чтение получателей под
  собственной блокировкой источника; AddRef/Release контроллеров.
- `fonts.cpp`: запуск адресного refresh на GTK-потоке, статус 95 при отказе.
- `test_text_rendering.py`: отдельные объекты и библиотеки Cairo/FT/HB,
  положительные/отрицательные лигатуры, геометрия и полутоновая растеризация.

## Данные и метаданные

N/A для метаданных. Протокол `.fonts` и настройки GUI сохраняются. Новый профиль
обнаружения содержит только проверенные runtime-адреса, номера слотов и смещение
кеша Font, полученные из инструкций. Фиксированных RVA и списков версий нет.

## Сквозные концепции

Все диапазоны чтения проверяются по mappings; исполняемые функции — по образу
платформы и unwind index. Список получателей ограничен; контроллеры удерживаются
до конца операции. До первого изменения проверяются все выбранные контроллеры.
Состояние документа, буфер текста, выделение и история не копируются и не меняются.

## Ключевые решения

Нативный setter выбран вместо подмены готовых глифов: так платформа сама
пересчитывает метрики. При несовместимости сохраняется работа новых редакторов
с предупреждением о переоткрытии, без разрушительного общего уведомления.

## Риски и недостатки

Структура платформы может измениться: строгая проверка должна отказать.
FreeType и ClearType могут давать разные пиксели; проверяется функциональное
поведение и геометрия, а не тождество двух растеризаторов.

## Допущения и открытые вопросы

Основной стенд — Linux x64/glibc, 1С 8.3.27.2325. Другие ABI требуют приёмки.

## Миграция и откат

Формат настроек не меняется. Новый engine загружается в новый процесс 1С;
старые процессы нужно один раз штатно переоткрыть. Установщик хранит версии.

## Трассируемость

MUST-1/3/5 → native text rendering tests; MUST-2 → editor_refresh + приёмка
в BSL; MUST-4 → текущий `.fonts`, GUI service и desktop regression.
