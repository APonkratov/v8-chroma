# Обновление portable-приложения

GUI проверяет GitHub Releases через 3 секунды после запуска и затем каждые
6 часов, в том числе в фоне. В настройках можно отключить автоматическую
проверку, включить предварительные версии RC и проверить обновления вручную.
Установка начинается только по кнопке «Обновить и перезапустить».

Версии сравниваются по SemVer. Черновики, неизвестные форматы тегов и версии
не новее текущей исключаются. По умолчанию RC также исключаются. При временном
сбое сети или GitHub фоновая проверка сохраняет последний успешный результат
и повторяется через две, а затем через пять минут. Ошибка появляется в настройках,
если оба повтора не помогли. При ручной проверке сообщение появляется сразу.

О новой версии сообщают баннер и системное уведомление от значка v8-chroma.
Версия запоминается после подтверждения показа от Windows. Если уведомление
не появилось, следующая проверка может повторить показ. Доступная версия
остаётся видна в баннере, в меню и в подсказке значка в трее.

## Проверка подлинности

В EXE встроен открытый ключ из `ui/src-tauri/update-signing.pub`.
Релиз содержит `SHA256SUMS.txt` и `SHA256SUMS.txt.minisig`. Приложение сначала
проверяет Minisign-подпись списка, включая подписанный комментарий
`v8-chroma vMAJOR.MINOR.PATCH` (либо тег с `-rc.N`), затем SHA-256 скачанного
EXE. Комментарий связывает байты с версией и не позволяет выдать старый
подписанный EXE за новый релиз. Полученный по сети открытый ключ не используется.

Адреса assets должны принадлежать выбранному релизу APonkratov/v8-chroma.
Соединения используют HTTPS, проверку сертификатов, таймауты и ограничения
размеров ответов. Токен GitHub для публичных релизов не нужен.

Подпись обновления не является Windows Authenticode и не меняет предупреждения
SmartScreen. Старые релизы без Minisign-подписи автоматически не устанавливаются.

## Установка и восстановление

В каталоге текущего EXE создаётся временная папка `.v8-chroma-update-*`.
Каталог должен быть доступен пользователю на запись. В неё скачивается новая
версия, сохраняются подпись и список сумм, копируется текущий EXE как помощник.
Дополнительный устанавливаемый компонент или PowerShell не требуются.

Если соединение оборвалось во время скачивания EXE, менеджер скачивает его
заново во временную папку. После первой попытки есть ещё две, через одну и
три секунды соответственно. Ошибки доступа, подписи и SHA-256 сразу видны.

Помощник запускается до завершения менеджера. Он повторно проверяет подпись,
версию, исходный процесс и оба файла, сообщает о готовности и ждёт завершения
исходного процесса. Затем переносит старый EXE в резервную копию, устанавливает
новый по прежнему пути и запускает его с исходными пользовательскими аргументами
и рабочим каталогом. Служебные аргументы обновления не накапливаются.

Новая версия подтверждает готовность после загрузки интерфейса и успешного
обмена между Svelte и Rust; одного создания окна недостаточно.
При ошибке замены или запуска помощник восстанавливает предыдущий EXE и
пытается запустить его снова. Если файл блокирует внешняя программа и восстановить
его не удалось, резервная копия `previous.exe` и `error.txt` остаются во временной
папке. Подтверждённые успешные обновления очищаются следующим запуском/службой.

Настройки и путь автозапуска сохраняются. Обновляется только GUI EXE;
отдельный CLI при необходимости скачивается с релиза вручную.
Загруженные в 1С DLL остаются в каталогах по хешу. Менеджер продолжает работу
с загруженной DLL, если проверенный файл отличается от встроенного только
метками времени компоновки. При других различиях открытый Конфигуратор
нужно штатно перезапустить.

Настройки проверки и отметка уведомления лежат в `updates.json` рядом с
`settings.json`, в том числе при `--config-dir`. Повреждённый файл отключает
автоматическую проверку до сохранения настроек пользователем.

## Ключ выпуска

Закрытый ключ хранится вне Git и передаётся publish-задаче через GitHub Actions
secret **`MINISIGN_SECRET_KEY`**. Не добавляйте его в репозиторий, артефакты
сборки, логи или память агента. Сохраните отдельную защищённую резервную копию:
потеря ключа лишит уже выпущенные приложения возможности принять новые обновления.

Для первичной настройки используется Minisign:

```powershell
minisign -G -W -s C:\secure\v8-chroma-update.key -p ui/src-tauri/update-signing.pub
Get-Content -Raw C:\secure\v8-chroma-update.key | gh secret set MINISIGN_SECRET_KEY --repo APonkratov/v8-chroma
```

`-W` создаёт ключ без пароля для автоматического CI; локальный файл необходимо
защитить правами доступа. Команда генерации нужна только один раз — при
существующем ключе используйте его, а не создавайте новый для каждого релиза.

Build-задача встраивает публичный ключ и включает его в release-артефакты.
Publish-задача проверяет суммы, подписывает список и проверяет подпись этим
публичным ключом перед публикацией. Отсутствующий или несовпадающий ключ
останавливает выпуск. Закрытый ключ недоступен PR/checks/build-задачам.

## Приёмка

- Проверка вручную и при запуске с открытым и свёрнутым окном; без сети/с HTTP 403.
- Stable/RC, равная и более старая версия; повторное уведомление после перезапуска.
- Изменённые EXE, список сумм, подпись и номер релиза должны блокировать установку.
- Успешная замена EXE с пробелами/кириллицей в пути; сохранение настроек,
  автозапуска, рабочего каталога, `--background` и `--config-dir`.
- Отказ записи, занятый EXE, ошибка старта новой версии и восстановление старой.
- Открытый конфигуратор с предыдущим движком получает предложение штатного
  перезапуска, без принудительного завершения 1С.
