# Linux x64: графический менеджер

В Linux доступен тот же менеджер тем, что и в Windows. Запускайте Конфигуратор
обычным способом: менеджер находит открытые и новые процессы текущего пользователя,
подключает движок и применяет выбранную тему. Запускать 1С через менеджер не нужно.
Файлы платформы и системные настройки загрузчика не меняются.

В интерфейсе доступны каталог тем с предпросмотром, список Конфигураторов,
ручное применение, выключатель автоприменения и сохранение настроек.
Если выбор отправлен во время фонового применения, он сохраняется;
при включённой автоматике последнее оформление применяется после текущей операции.
Смена темы вызывает перерисовку GTK-окон, перезапуск 1С не требуется.
Доступны тот же набор значков, выбор семейства и размера шрифта редактора,
отдельный шрифт интерфейса и варианты «Штатные» / «Как в 1С».
Программные лигатуры определяются выбранным семейством, отдельного переключателя
нет. В Linux используется штатный HarfBuzz/FreeType/Cairo: подтверждены JetBrains
Mono Medium с лигатурами и Consolas без них, в том числе в BSL-режиме с кириллицей
и табуляцией. Сглаживание использует штатные настройки растеризатора; на стенде
1С передаёт Cairo SUBPIXEL/SLIGHT. Пиксели FreeType и Windows ClearType могут
различаться из-за алгоритма, DPI и устройства вывода.
Коррекция некоторых растровых текстур интерфейса Windows сюда не переносилась.
Полнота оформления диалогов, печать и экспорт требуют отдельной проверки.

## Сборка и установка

Требуются Linux x86-64 с glibc, Rust из `rust-toolchain.toml`, Node.js 24,
CMake 3.25+, Ninja, GCC и Python 3.11+. Для Ubuntu 24.04:

```bash
sudo apt-get install --no-install-recommends \
  g++ cmake ninja-build pkg-config libcairo2-dev libfontconfig1-dev fontconfig \
  libharfbuzz0b fonts-dejavu-core fonts-firacode libx11-6 libxext6 libxrender1 \
  python3-venv libwebkit2gtk-4.1-dev libayatana-appindicator3-dev \
  librsvg2-dev libxdo-dev libssl-dev patchelf
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r scripts/requirements-ci.txt
python scripts/build.py linux-desktop
python scripts/install_linux.py
```

Установщик создаёт пункт **V8 Chroma** в меню приложений пользователя.
WSLg может перенести его в меню Windows. Если пункт не появился, из PowerShell
в каталоге проекта один раз выполните `./scripts/install_wsl_shortcut.ps1`.
Он создаёт пункт **V8 Chroma (Ubuntu-24.04)** через `wslg.exe`, без консоли
(`-Desktop` добавляет также ярлык рабочего стола);
другой дистрибутив задаётся параметром `-Distribution`.
Путь установленного приложения может содержать пробелы и кириллицу. Имя
дистрибутива для прямого запуска через `wslg.exe` должно быть без пробелов и
кавычек: его парсер отвергает даже заключённое в кавычки `Ubuntu-24.04`.
Дальше терминал для использования менеджера не нужен. Preview можно открыть
непосредственно: `dist/linux-preview/v8-chroma`; рядом должны лежать
`libv8-chroma-linux.so` и `v8-chroma-injector`.

Файлы установки находятся в `$XDG_DATA_HOME/v8-chroma/app`
(по умолчанию `~/.local/share/v8-chroma/app`), ярлык — в
`~/.local/share/applications/v8-chroma.desktop`. Обновление создаёт отдельную
версию и атомарно переключает ссылку; файлы запущенных процессов не перезаписываются.

На обычном Linux-десктопе менеджер использует доступный системный трей и
автозапуск при входе. В WSLg трея обычно нет: закрытие окна завершает менеджер,
для наблюдения оставьте его открытым или сверните. Автозапуск при входе в Linux-сеанс
в WSLg недоступен, соответствующий переключатель отключён.

## Проверки и CLI

`python scripts/build.py linux` собирает движок и диагностический CLI без GUI.
Обе команды сборки выполняют native-тесты, проверки палитр, изоляции Cairo,
подключения к уже работающему процессу, жизненного цикла CLI и Rust tests/Clippy.
`linux-desktop` дополнительно проверяет frontend и общий desktop service.
GUI-сценарии запускаются через WebKitGTK WebDriver (`webkit2gtk-driver`):

```bash
python native/linux/test_desktop.py --app dist/linux-preview/v8-chroma \
  --fixtures build/native/linux-gcc/linux
```

Тест нажимает настоящие кнопки: проверяет ручное применение, выключенную
автоматику, подключение открытого и нового собственного процесса, смену темы,
повторное включение наблюдения и пропуск режима «Предприятие».
Проверяются также значки, оба семейства шрифтов, размер текста и возврат
штатного оформления. При выключенной автоматике выбор сохраняется без отправки в 1С.
В CI он выполняется в отдельном D-Bus-сеансе под Xvfb.

Для проверки собственной программы на Cairo установленной 1С:

```bash
python scripts/build.py linux-desktop \
  --cairo /opt/1cv8/x86_64/8.3.27.2325/libcairo-v8.so
```

Тесты используют собственные процессы и не требуют лицензии. Для приёмки
реального интерфейса нужны платформа, лицензия и отдельная тестовая база.
Диагностический CLI остаётся доступен:

```bash
./dist/linux-preview/v8-chroma-linux list
./dist/linux-preview/v8-chroma-linux attach --pid 12345 --theme dracula
./dist/linux-preview/v8-chroma-linux apply --pid 12345 --theme github-light-default
./dist/linux-preview/v8-chroma-linux apply --pid 12345 --theme standard
./dist/linux-preview/v8-chroma-linux status --pid 12345
```

`status` разделяет загрузку и работу перехватов: `hook_mask`, `observed_calls`
и `mapped_calls` показывают зарегистрированные функции и реальные вызовы.
Наличие сессии само по себе не подтверждает полноту перекраски интерфейса.
Старый диагностический `launch` с `LD_AUDIT` сохранён; для обычной работы GUI
он не используется.

## Подключение и ограничения

После обновления со старого движка без значков и шрифтов уже открытый
Конфигуратор нужно один раз перезапустить. Загруженные библиотеки не заменяются
в памяти. После подключения нового движка семейства, размер, значки и цвета
меняются без перезапуска; для отдельных диалогов может потребоваться переоткрытие.

Список шрифтов поступает из Fontconfig. Файлы шрифтов в preview не включаются.
В локальном WSL подключены установленные на этом же компьютере Segoe UI Variable,
Consolas и JetBrains Mono Medium через ссылки в пользовательском каталоге шрифтов.
В Linux имя Segoe UI Variable Small сопоставляется с Segoe UI Variable;
если этого файла нет, используется системное sans-семейство с пояснением
в карточке процесса. Для других отсутствующих семейств отображается ошибка.
Fira Code и DejaVu в команде сборки нужны для положительного и отрицательного
контроля в тестах; шрифты не входят в пакет приложения.

Значки заменяются только при совпадении размеров и отпечатка исходных пикселей.
Неизвестные изображения сохраняются. Две библиотеки Cairo имеют отдельные кеши;
проверяются матрица, масштаб, смещение, фильтр, альфа-канал и динамические образцы
цвета. Обработка значков ограничена экранными surface, экспортные surface пропускаются.

Шрифты меняются в проверенных импортах `grphcs.so` и `frame.so`.
Проверяются LP64/UTF-16 структура и layout штатных типов шрифта; явно заданные
семейства документов, фиксированные штатные и символьные шрифты не подменяются
интерфейсным семейством. Обновление выполняется на GTK-потоке: для интерфейса
отправляется событие оформления, для редакторов вызывается только штатная цепочка
пересчёта шрифта. Общее событие параметров текста не отправляется: оно сбрасывает
состояние BSL-адаптера. Источник, контроллеры и цепочка Font проверяются по
инструкциям и границам ELF-функций; при несовместимости предлагается переоткрыть
редактор. Настройки хранятся в отдельном двоичном файле `.fonts` рядом
с конфигурацией сессии; двоичный протокол Windows не меняется.

Загрузчик через `ptrace` подключается только к процессам `1cv8`, запущенным
текущим пользователем в режиме `DESIGNER`. Проверяет PID, starttime из `/proc` и EXE до и после
остановки потока, сохраняет и восстанавливает его регистры, включая SIMD.
Точка возврата вызова libc подтверждается точным RIP собственного breakpoint.
Если вызов длится более пяти секунд, загрузчик продолжает ждать его безопасного
завершения под ptrace; прерывать libc откатом регистров нельзя. При неустранимой
блокировке libc это ожидание также не завершается автоматически.
Библиотека загружается отдельным потоком после продолжения основного потока.
Затем движок проверяет компактную таблицу функций Cairo в writable-сегментах
`grphcs.so` и атомарно заменяет совпавшие указатели. При неподдерживаемой таблице
подключение отклоняется. Режим «Предприятие» не поддерживается.

Политика Linux должна разрешать подключение процессов одного пользователя.
При запрете `ptrace` ошибка видна в списке Конфигураторов. Менеджер не запрашивает
root и не меняет Yama, capabilities или другие системные ограничения.
Локальная WSL 2 Ubuntu 24.04 разрешает этот сценарий без дополнительных настроек;
обычный Linux-десктоп с другой политикой требует отдельной настройки администратором.

Установленная 1С использует как `libcairo-v8.so`, так и системный Cairo,
уже загруженный GTK. У них отдельные исходные указатели: контексты не смешиваются,
обычные привязки GTK остаются штатными. Перекрашиваются вызовы таблицы 1С.

Конфигурация использует двоичный протокол v3 с фиксированными 32-битными полями
и UTF-16. Повреждённый, чужой или доступный для записи другим пользователям файл
отключает подмену цветов. Неизвестные цвета и альфа-канал сохраняются.
Runtime в пользовательском каталоге `v8-chroma/linux` имеет права 0700;
библиотеки копируются под SHA-256, сессии привязаны к PID/starttime/EXE.

Локальный стенд: Ubuntu 24.04 x64 в WSL 2/WSLg, платформа 8.3.27.2325 x64.
Проверены дерево конфигурации, редактор модуля и смена палитр в одном процессе.
Проверены GUI-сценарии, запуск установленного ярлыка и автоматическое подключение
к новому обычному запуску настоящего Конфигуратора без `LD_AUDIT`.
Проверены новые значки в дереве/панелях, кириллица в текстовом редакторе,
горячая смена JetBrains Mono Medium 13 pt / Consolas 20 pt и смена интерфейсного
семейства, включая заметно различающиеся serif/monospace варианты.
В BSL-редакторе проверены ввод между символами `<=`, сохранение выделенной пары,
Undo/Redo через горячую смену JetBrains Mono 13/19.5 pt и Consolas 20 pt,
возврат штатного шрифта. Содержимое собственного файла сверялось целиком после
сохранений. Нативные проверки сравнивают glyph clusters и позиции символов,
режимы NONE/GRAY/SUBPIXEL на светлом/тёмном фоне и масштабы 100/125/150/200%.
Все 13 палитр проверяются на собственных контекстах Cairo. Другие версии платформы
и обычный Linux-десктоп требуют отдельной приёмки. Релизный workflow пока
выпускает только Windows.

Дополнительные проверки установленного шрифта и библиотек платформы:

```bash
python native/linux/test_text_rendering.py --family 'JetBrains Mono Medium' --require-ligatures
python native/linux/test_text_rendering.py --family Consolas --expect-no-ligatures
python native/linux/test_text_rendering.py --cairo /opt/1cv8/x86_64/8.3.27.2325/libcairo-v8.so \
  --family 'JetBrains Mono Medium' --require-ligatures
```

Технические критерии и причины выбора штатного shaping описаны в
[спецификации](linux-text-rendering.md) и [дизайне](linux-text-rendering-design.md).
Справка API: [HarfBuzz features](https://harfbuzz.github.io/shaping-opentype-features.html),
[Cairo font options](https://www.cairographics.org/manual/cairo-cairo-font-options-t.html).
