# Платформы и переносимость

## Текущее разделение

| Часть | Состояние |
|---|---|
| Палитры, предпросмотр, кодировщик протокола | Общий Rust-код, без Windows API |
| Настройки и политика применения | Общий код и модель process::Identity |
| Атомарная запись | MoveFileExW на Windows; rename и синхронизация каталога на Unix |
| Обнаружение 1С, доступ к процессу, загрузка движка | Windows x64 (`windows-engine`), Linux x64 (`linux-engine`) |
| Перехваты отрисовки | C++ Windows x64 и Linux x64, сборка CMake/Ninja |
| Desktop shell и CLI с подключением к 1С | Windows x64 и экспериментальный Linux x64 |

Linux x64 использует общий графический интерфейс и наблюдатель, отдельные
ptrace-загрузчик и Cairo-backend: [сборка, запуск и ограничения](linux.md).
Менеджер подключается к открытым и новым Конфигураторам; темы, значки,
шрифты редактора и интерфейса применяются общим наблюдателем.
В WSLg без трея закрытие окна завершает приложение.

Для проверки общего ядра feature движка отключается:
`cargo test -p v8-chroma-core --lib --no-default-features`.
В этом режиме не нужна собранная DLL и не выполняется подключение к процессам.

## Матрица CI

| ОС | Архитектура | Задача |
|---|---|---|
| Windows | x64 | Полная проверка native, Rust, UI и CLI |
| Windows | ARM64 | Проверка общего ядра |
| Linux | x64, ARM64 | Проверка общего ядра |
| Linux | x64 | Подключение к работающему процессу, Cairo, CLI, frontend и desktop service |
| macOS | Intel, Apple Silicon | Проверка общего ядра |

Workflow задаёт отдельный runner для каждой цели. Локальные
`cargo check --target` проверяют компиляцию для других целей;
выполнение тестов требует соответствующей платформы.

Релизные артефакты доступны для Windows x64. Строка в матрице ядра не означает
готовность GUI или перекраски на этой платформе. При сборке для неподдерживаемой
платформы CMake выдаёт явную ошибку; фиктивные DLL/движки не выпускаются.

## Дальнейший перенос

Для остальных платформ потребуются реализации обнаружения
процессов, проверки их идентичности и архитектуры, загрузки движка и перехватов.
Также нужно перенести открытие каталога/ошибки desktop shell и проверить работу
с целевым конфигуратором 1С. Поддержка каждого backend определяется этими
проверками, а не одной успешной сборкой Tauri.

Для ARM64 необходимо различать архитектуру менеджера и целевого процесса 1С:
ARM64-приложение не может просто использовать текущую x64 DLL для ARM64-процесса.
Если целевой 1С работает в эмуляции x64, это отдельный сценарий проверки.
Наличие подходящей платформы/конфигуратора 1С проверяется до реализации backend.

После реализации и приёмки backend расширяются сборки GUI/CLI и релизная матрица.
Системные компиляторы: MSVC на Windows, GCC/Clang на Linux, Apple Clang на macOS.
