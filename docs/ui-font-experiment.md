# Эксперимент: шрифт интерфейса конфигуратора

**30 октября 2026: шрифт можно менять в уже открытом конфигураторе без
перезапуска процесса.** Проверено на 1С 8.3.27.2325 x64.

Для нового оформления выбран **Segoe UI Variable Small**, резервный — Segoe UI.
Сравнение выполнено в реальном интерфейсе при исходном логическом размере:

| Семейство | Наблюдение |
|---|---|
| Segoe UI | Компактный Windows UI; уже используется в интерфейсе менеджера v8-chroma. |
| **Segoe UI Variable Small** | Более ясная мелкая кириллица, чуть свободнее строки и панели. Выбран для продолжения. |
| Roboto | Аккуратный и компактный, но характер начертания меньше соответствует остальному Windows-интерфейсу. |

Это визуальная оценка конкретного оформления. Другие размеры и мониторы могут
изменить предпочтение. Семейство Segoe UI Variable используется в современном
Windows UI: [Microsoft Typography](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/typography).
Шрифты не входят в сборку: используются установленные семейства.

## Как удалось убрать перезапуск

Подмена CreateFontIndirectW, преобразований abs_font_to_logfont /
adjust_stock_font и создания Cairo font face обслуживает новые шрифты.
Однако 1С сохраняет расчёты текста существующих элементов.
Одних WM_FONTCHANGE, WM_SETTINGCHANGE, WM_THEMECHANGED и перерисовки
для согласованного обновления недостаточно.

Рабочее решение — после смены семейства отправить **штатное событие 1С
kDefaultStyleChangedEvent на GUI-потоке**. Оно пересчитывает текст, строки
дерева, меню и панели. Текст, выделение и история проверенного открытого
текстового документа сохраняются.

Источник события обнаруживается по последовательности реального вызова
уведомления в core83/core85 и ссылке на экспортированный GUID. Фиксированных
RVA, хешей или списка разрешённых версий нет. Проверяются PE x64, границы
функций и layout источника событий. Незнакомая структура возвращает
ERROR_NOT_SUPPORTED. Диспетчер использует временный WH_CALLWNDPROC только
на GUI-потоке выбранного процесса, зарегистрированное сообщение и таймаут.

Имитация смены DPI не нужна. Такой диагностический опыт был отброшен:
начертание менялось, но оставались старые ширины и обрезались подписи.
Пробный перехват correctSymbolFont также не решил задачу и удалён.

Системные шрифты Windows, файлы платформы и настройки базы не меняются.
Эта часть описывает первоначальный прототип. Итоговая интеграция описана ниже.

## Проверка без перезапуска

В отдельных тестовых базах проверены позднее подключение движка, переходы
Segoe UI → Segoe UI Variable Small → Roboto и возврат к параметрам 1С.
Текст, выделение и история Undo/Redo собственного текстового образца сохранились.
В продуктовой интеграции отдельно проверено позднее включение шрифта редактора
и независимость явно заданных шрифтов табличного документа.
Матрица проверенных платформ и ограничения приведены в [fonts.md](fonts.md).

## Уже открытые диалоги

У «Параметров», открытых **до** смены семейства, может остаться старая ширина
отдельных подписей. Нужно закрыть и открыть этот диалог снова: новый экземпляр
показывает надписи полностью. Конфигуратор и документы остаются открытыми.
Полное обновление геометрии всех уже открытых диалогов пока не решено.

## Итоговая интеграция

Продуктовый движок `native/src/ui_font.cpp` использует четыре импорта:
CreateFontIndirectW в frame, stock-преобразование в grphcs/frame и
abs-преобразование только в frame. Для преобразований дополнительно проверяется
признак штатного шрифта платформы. Импорт abs-преобразования в grphcs остаётся
доступным независимому движку шрифта редактора, в том числе при его позднем включении.

Широкие перехваты Cairo и загрузчика модулей, удержание HFONT и диагностические
записи на каждой отрисовке из прототипа не используются. Не нужны ранний запуск,
подмена DPI и специальные команды управления экспериментом.

Настройки, резервный Segoe UI, общий флаг автоприменения, пункт «Как в 1С» и
диагностика отдельного процесса встроены в GUI и CLI. Подробности — [fonts.md](fonts.md).
Диагностический прототип в сборку продукта не входит.
